# ■ Playgroundの確認手順

数値は [expected_results.json](../expected_results.json) と照合します。文章表現はモデルや会話履歴によって変わります。

## ● 基本の質問

**1) 八王子市の変化**

```text
八王子市の2020年から2025年の変化を、人口、単独世帯割合、
65歳以上割合の観点で教えてください。年齢不詳率への注意点もお願いします。
```

人口増減率−0.85%、単独世帯割合差+3.54pp、65歳以上割合差+2.94pp、年齢不詳率差+11.39ppを確認します。表示済みの割合から差を引き直さないことも確認します。

**2) 人口増減率上位**

```text
2020年から2025年の人口増減率が高い市区町村を、上位5つ教えてください。
```

台東区7.85%、中央区7.48%、江東区5.57%、墨田区4.76%、港区4.60%の順です。人口の多さや増加人数の順ではありません。

**3) 類似地域**

```text
八王子市に似た変化をしている地域を5つ教えてください。
何を基準に似ていると判断したのかも説明してください。
```

羽村市、渋谷区、日の出町、青梅市、多摩市の順です。距離は3指標の変化を標準化した距離で、地理的距離ではありません。

**4) クラスタ**

```text
クラスタ0とクラスタ1の違いを説明してください。
年齢不詳率の扱いも含めて、解釈上の注意点を教えてください。
```

クラスタ0は17地域、クラスタ1は44地域です。年齢不詳率差の平均に使える地域は11件・44件で、クラスタ0の6件のNULLをゼロに置き換えないことを確認します。平均は自治体ごとの単純平均です。

## ● Traceの確認

PlaygroundのTest detailsで、該当する質問を展開します。`tools.task` 配下の対象ツールを選択します。

| 確認対象 | 例 |
|---|---|
| ツール名 | `get_area_metrics` |
| Input | `inputs.area_code: 13201` |
| Output | ツール名、`status: success`、返却値 |
| 回答との一致 | 年齢不詳率差が11.39など |

OutputのJSONが横に長い場合はコピーし、`ToolMessage` の `kwargs.content` に入っている結果を確認します。ブログの実行では `structuredContent.rows` に行データがありました。

回答文の「使用ツール」は呼出しの証拠にはなりません。親AgentのOutputに含まれる過去のToolMessageと、その質問で新たに実行したSpanを区別します。

## ● Skillと同一セッションの会話

**1) Skill追加後、新しいセッションで実行**

```text
tokyo_census_interpretation のSkillを使用して、
八王子市の2020年から2025年の変化を説明してください。

SQLツールでデータを取得し、人口増減率、単独世帯割合の変化、
65歳以上割合の変化、年齢不詳率の変化を示してください。

%とppの違い、65歳以上割合の分母、
年齢不詳率を踏まえた解釈上の注意点も説明してください。
```

`activate_skill` のInputに `tokyo_census_interpretation`、Outputに `success` があることを確認します。これは読み込みの確認で、Skill単独の回答品質改善を示す比較ではありません。

**2) 同じセッションで類似地域を質問**

```text
先ほど調べた市と変化パターンが似ている地域を、
距離が小さい順に5つ教えてください。
```

八王子市を特定し、`find_similar_areas` に13201を渡すことを確認します。

**3) 同じセッションで比較**

```text
今の一覧の2番目の地域と、最初に質問した市について、
両地域のデータをSQLツールで取得し、
人口増減率、単独世帯割合の変化、65歳以上割合の変化を比較してください。
年齢不詳率への注意点も説明してください。
```

| 指標 | 八王子市 | 渋谷区 |
|---|---:|---:|
| 人口増減率 | −0.85% | −2.07% |
| 単独世帯割合差 | +3.54pp | +2.98pp |
| 65歳以上割合差 | +2.94pp | +1.76pp |
| 年齢不詳率差 | +11.39pp | +13.20pp |

ブログのこの実行では、地域の特定と数値は一致しましたが、SQLの再実行はTraceにありませんでした。過去の取得値を使ったと考えられます。「両地域のSQL再取得に成功」とは判定していません。再取得が必要な用途では、Traceとフロー構成の追加検証が必要です。
